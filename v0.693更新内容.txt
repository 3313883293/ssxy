v0.693 更新内容：「创伤」重构——改为「拥有者自己投币时伤口崩裂」的自伤型 DoT

用户要求：「和我的设计不符，改成是创伤的拥有者自己投掷硬币时受伤」

确认口径（二选一问答）：
① 结算次数：**按本次投出的硬币总数**结算（3 币技能 = 3 次 × 级数×20、消耗 3 层）
② 致死处理：**本次出招整体作废**——不投币、不造成伤害、不施加状态，直接走死亡结算

## 一、设计口径：创伤从「挨打惩罚」变成「出手惩罚」

| | 旧（v0.684~v0.692） | 新（v0.693） |
|---|---|---|
| 触发者 | **被打的目标**（谁打他谁引爆伤口） | **创伤的拥有者本人**（自己出招才撕裂伤口） |
| 触发时点 | 伤害循环内：投币之后、伤害之前 | 出招开头：**本次硬币掷出之前** |
| 触发次数 | 本次分配到该目标身上的硬币数 | **本次投出的硬币总数**（= 技能硬币数） |
| 每次效果 | 层数 −1 + 级数×20 真实伤害 | 不变 |
| 致死结果 | 目标被反噬致死（攻击者记击杀） | **施放者自己的本次出招作废**（失败即失败，不产生击杀归属） |
| 未变 | 真伤走 `takeTrueDamage`（守护转移仍可拦）、计入 `dotDamageMap['trauma']`、层数耗尽即消失、无回合末衰减；施加途径仍是多能战警【远程狙击】2 层 Lv2 /【交叉火力】狙击装参与 3 层 Lv3 | 同左 |

一句话：**「身上有伤还硬要出手 → 伤口崩裂」**。硬币越多越痛（与技能硬币数直接挂钩），不投币的技能（【焚香】【火灵召唤】等 0 币技能）与无目标技能一律不触发。

## 二、代码改动（唯一机制改动：判定对象 target → actor）

位置：`js/SkillSystem.js` 的 `executeSkill`。

- **旧**：位置在 `coinDist.forEach` 的目标循环内（`:416-436`），判定 `target.getBuffStack('trauma')`、次数 `coins`。
- **新**：位置在 `executeSkill` 开头（交叉火力连携解析之后、witness 标记 / 动画 / 技能自带 buff / 焚香 / 召唤 / 守护层数**之前**），
  判定 `actor.getBuffStack('trauma')`、次数 `skill.coinCount`，逐层结算，**施放者一旦倒下立即 `return`**。
- 为什么放在这个位置：① 交叉火力在该点才把 targets 解析完（`targets.length > 0` 才能判断「本次会不会投币」）；
  ② 早于 witness 标记 → 被崩裂打断的【开创】不算「使出过」；③ 早于动画/技能自带 buff/焚香/召唤/守护 → 「作废」是真的作废。
- 顺带修掉两个 v0.692 审计发现的缺陷：
  ① **创伤致死重复结算**（旧实现里 `handleDeath()` 被调用两次 → `totalDeaths` +2、击杀情感 +1 变 +2、日志多一条「造成 0 伤害」、
  待命区可能多拉一名补位）——本版只调用一次 `handleDeath()` 后 return，该问题随重构消失；
  ② **结算页 Dot 明细漏列「创伤」**（`dotTypeCfg` 是硬编码白名单，只写了燃烧/混乱）——本版补上 `🩸 创伤` 行，
  并修正注释（写明「新增 DoT 必须手动加一行」，原先注释误称会自动分列）。
- 已知边界（记录在案、当前不可达）：创伤段位于交叉火力连携之后，理论上「带创伤的多能战警放【交叉火力】」会先扣伙伴算力、
  先播连携演出，之后才崩裂作废；但创伤只有多能战警能施加，而多能战警既不在玩家可选池、也不会成为创伤持有者 → 走不到。

## 三、文案同步

  触发次数 = 本次投出的硬币总数（不投币的技能不触发）；若崩裂致死，本次行动作废」。
