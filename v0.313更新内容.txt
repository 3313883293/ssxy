v0.313 更新内容：每回合自动存档 + 战斗中一键读档回本回合开始 + 刷新后续战

用户需求：战斗存档机制。经确认采用「自动存档 + 读档」方案：每回合开始自动存一次，战斗中可一键读档回到本回合开始，刷新页面后可继续战斗。

## 改动

**回合开始自动存档（battleFlow.js）**：
- 新增 `saveAutoBattle()`：在 `startNewRound` 的回合初始化完成后、行动开始前（`processNextAction()` 前）同步写入 localStorage `pwgame_battle_save`，含关卡、回合数、总阵亡数、召唤池、敌我全部队伍（出场 + 待命）、globalId
- `serializeChar()`：角色 → 可 JSON 快照（hp/sp/speed/speedMin/speedMax/def/buffs/order/position/aiControlled/aiCycle/aiIndex/defector/hateReduction/pendingEntry/entryAnim/intentSkill/dotDamageMap/伤害统计/actedThisTurn 等）；怨灵额外记 `_wraithType` 标记（Roles.js 的 `createPoliceWraith` 新增字段），读档时经 `createPoliceWraith` 重建（保留 HP 减半）
- 第 1 回合开始（turnCount>=1）才存档；战斗开始但未开回合时无存档

**读档（battleFlow.js）**：
- `loadAutoBattle()`：重建角色实例（普通角色走 `createRoleInstance`、怨灵走 `createPoliceWraith`）→ 覆盖快照字段 → 恢复召唤池/回合数/总阵亡数/globalId → `buildActionQueue()` 按存档速度重建行动队列 → `processNextAction()` 从本回合开始继续
- `buildActionQueue()`：从 startNewRound 抽出的速度排序逻辑，startNewRound 与读档共用，保证行动顺序一致
- 战斗中「↩️ 读档」按钮（`#loadSaveBtn`，战斗页头部，存档存在时显示）调 `loadSaveFromBattle()`（confirm 确认后回到本回合开始）
- 标题页「▶️ 继续战斗」按钮（`#continueBtn`，有存档时显示）调 `continueBattle()`，刷新/重开后恢复未完成战斗

**异步推进的纪元防护（battleFlow.js + battleActions.js）**：
- 新增 `battleEpoch` 全局计数：`startBattle`/`startCustomBattle`/`backToTitle`/`loadAutoBattle` 时递增
- `scheduleProcessNext(delay)`：替代 battleActions.js 中 7 处行动推进 `setTimeout`（玩家自动跳过、executePlayerAction 后、敌方行动后），回调内校验纪元，读档/重开后的旧回调一律丢弃；敌方行动外层 900ms 延迟也加 epoch 检查——读档瞬间的挂起动画/行动不会污染新状态
- 读档后旧 DOM 上的确认/取消/跳过按钮随 `innerHTML` 重建自然失效，无需额外处理

**战斗结束清档（battleUI.js）**：
- `showResultPage` 开头 `clearBattleSave()`：战斗有结果（胜/负）即清除自动存档，主界面不再显示「继续战斗」，战斗中「读档」按钮隐藏

## Bug 修复：读档后角色 id 冲突（点击怨灵卡弹错详情 + 无法选中）

**现象**（第四关）：读档/刷新续战后继续打，云长郡再次召唤怨灵，使用技能点击警察怨灵时弹出的是**鲁盼旋的被动详情**，且怨灵无法被技能选中。

**根因**（battleFlow.js loadAutoBattle）：读档重建角色时 `globalId` 沿用当前较大的值分配新 id，重建完成后却 `globalId = data.globalId`（存档时的较小值）——下次创建角色（再召唤怨灵等）分配到的 id 会撞上重建角色的 id。卡片点击走 `findCharacterById(cardId)`（battleUI.js），id 冲突时返回第一个匹配 → 解析成重建的玩家角色（如鲁盼旋）→ 该角色 team='player'，既跳进 `showSkillInfo` 弹错详情，又不满足「enemy + selectable」而无法选中。

**修复**：读档重建前 `globalId = 0`，重建全部角色（出场+待命）从 0 连续分配，重建完成后 `globalId` = 全部重建角色数；移除「恢复存档 globalId」的逻辑。验证：verify-v313.js 新增测试 H（构造存档时 globalId 与当前一致的最易冲突场景 → 读档 → 再召唤 → 断言 id 全唯一 + findCharacterById 返回正确怨灵），23 项全过。
