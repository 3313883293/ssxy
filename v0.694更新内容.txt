## 一、架构：声明式步骤表 + 事件通知（核心交付）

### 1. 旧实现的病根
推进判据 = 「当前步 id」，散落在 5 个文件 10 处特判（各处自行比较当前步 id 再调 `advance(id)`）。
`advance(id)` 是**自证式接口**——传入 id 与当前步不符就静默 `return`：漏改任一调用点 → **教程卡死且无任何报错**。
步骤编号 ①~⑫ 还硬编码在文案里，与「步骤 N / 12」标题、进度条圆点**三处不同源**。

### 2. 新结构（`js/tutorial.js` 整体重写，414 行）

```
TUTORIAL_STEPS[i] = { id, page:'select'|'battle', text, mode:'force'|'info'|'end',
                      advanceOn, refreshOn, gates, highlight }   // 每步一个推进事件，全局唯一
业务代码只发事件：tutNotify(TUT_EVENTS.XXX)      // 一行、不带步骤 id、无需 typeof 守卫
Tutorial.notify(ev)  → 命中 advanceOn 则推进；命中 refreshOn 则重刷；否则记 trace(miss)
Tutorial.gate('skipTurn')  → 按钮门控查询（业务代码不再认识步骤 id）
```

- **8 个事件**（`TUT_EVENTS`）：`char-slotted` / `level-confirmed` / `round-started` / `skill-picked` /
  `target-picked` / `action-confirmed` / `enemy-acted` / `turn-skipped`。
- **mode 语义**：`force` 强制步（无「知道了」、✕ 不可关，只能靠事件推进）／`info` 图文步（可关；
  **声明了 advanceOn 就只关不推进**，未声明则「知道了」= 推进）／`end` 结束步（点击即解除教学）。
  `dismissable` / `okAdvance` 由 mode 派生 → 单一事实来源。
- **编号自动生成**：`TUTORIAL_NUMBERING[步骤索引]`，正文前缀 / 标题步骤号 / 进度条圆点三者同源。
- **可观测（禁止继续静默失败）**：`Tutorial.trace`（begin/advance/refresh/miss/inactive 环形缓冲）+
  `Tutorial.warnings`（未知事件名、`advance(id)` id 不匹配、高亮目标缺失）+ `console.debug/warn`。
- **步骤表自检**：载入即跑 `Tutorial.selfCheck()`——id 唯一 / 事件唯一 / 推进来源 / gate 显式声明 /
  mode·page 合法 / 文案无硬编码编号；问题数组 + `console.warn`，验证脚本直接断言 `length === 0`。

## 三、机制图鉴（新增 `js/codex.js`，102 行）

教程主线只有 12 步、手机端正文预算很紧（短高横屏 240px），结构类与后期机制既无法在 1v1 训练场实操、
塞进弹窗又会顶破高度预算 → 集中到图鉴（**纯表现层弹窗**，不进 `showPage` 流程，不影响教程 `syncPosition`）：

1. ⚔️ 战斗流程与速度（速度区间重随机、我方优先与站位排序、【加油】/【刹车】与【开创】速度差、意图徽章）
2. 📐 站位、待命区与补位（只看距离 / 死亡后自动重排 / 每边至多 3 名 / 补位时点 / 胜利含待命角色）
3. 💢 状态一览（持续伤害 / 控制 / 防护 / 强化 / 其他——**被制服、守护、守护之躯、狂炎、休整都在这里**）
4. 🔁 被动与主动（差别 + 查看入口）
5. 🌀 技能形态与装备切换（曹佳梦厌倦 ↔ 陨星；多能战警按站位换装 + 只能使用当前装备技能）
6. 👻 召唤与倒戈（云长郡怨灵 / 李雅礼倒戈）
7. 🏆 胜负与星级（基础胜利 + 特殊胜利 + 星级解锁 + 教程/测试关不计星）
8. 💾 存档与继续战斗（自动存档时点 / 读档 / 战斗结束清档 / **教程进度单独保存可续教**）

入口：主界面与关卡选择页各一个【📖 机制图鉴】按钮（`index.html`）；`#codexOverlay` z-index 1500
（高于设置弹窗 999、低于词条弹窗 2100 —— 图鉴里点词条时词条仍在最上层）。文案内 Buff/状态名一律
`renderGlossaryText` 渲染 → 词条可点，数值与触发时点仍以词条为唯一来源。

## 四、教程进度存档（v0.694 修掉陷阱 §6.5）

现状缺口：教程关开局会写 `pwgame_battle_save`，但**战斗存档不序列化教学进度**——刷新后从主界面
「继续战斗」进入会完全没有教学引导。

- 新增两个**独立 key**（**不动 `pwgame_battle_save` 结构**）：`pwgame_tutorial_step`（当前步索引，每步写入）、
  `pwgame_tutorial_done`（走完 ⑫ 写 '1' 并清掉进度）。
- `Tutorial.resume()`：已完成 → 不打扰；有进度 → `begin(存下的步)`。
- 调用点：`loadAutoBattle`（主界面「继续战斗」/ 战斗中「读档」后，`currentLevel === -2` 且教学未激活时）+
  `restartBattle`（教程关「再来一局」）。
- 完成教程后想从头重看：回关卡选择页再进一次【🎓 新手教程】（`confirmLevel` → `begin(0)`，清完成标记）。
- **自愈说明**：恢复到某步时局面可能与该步不匹配（如恢复到⑤但技能还没选）——事件化后
  「不匹配事件只记 trace(miss) 不推进」，玩家重做前置操作即可继续推进，不会卡死。

## 九、已知边界与待确认

1. **`resume()` 恢复到的步骤可能与局面不匹配**（如恢复到⑤但技能未选）：靠「不匹配事件不推进」自愈，
   玩家重做前置操作即可继续。未做「按局面回退步骤」的智能推断（属多余复杂度）。
2. 教程进度**跨关卡共享一个 key**：教程关进度只在 `currentLevel === -2` 时被使用，其他关卡不受影响；
   但若玩家在教程关存了进度、又去玩正式关，正式关不会触发 `resume()`。
3. 图鉴 8 个分区的内容是**图文 + 词条**，不含数值表（数值仍以词条 / 敌方详情为唯一来源）；日后新增机制
   按 CORE_MECHANICS C75 五处同步，其中「结构类机制」的落点是 `codex.js`。
4. `check-v0664-text.js` 的 A10（⑨「昏迷」括号措辞）在 v0.693 基线上**就已经失败**（v0.667 时点统一改过措辞），
   本版未恢复旧措辞（新措辞遵循《触发时点术语表》「轮到行动时无法行动，跳过本次行动后解除」）。
5. 教程关依旧不发星、不写 `pwgame_cleared`、`restartBattle` 之外没有其他重播入口——与 v0.693 一致
   （`restartBattle` 现在会 `resume()`，属新增行为，已在更新内容与本表说明）。
