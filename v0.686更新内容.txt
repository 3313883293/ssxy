v0.686 更新内容：多能战警初始算力改为 0——攒算力型敌方单位

## 背景

用户要求：多能战警初始算力设为 0。原实现（v0.684 起）构造时按 Character 默认规则
`sp = maxSP`，多能战警开场即满算力 400，第一回合就能施放【交叉火力】（连携技，400 算力）。
改为 0 后，多能战警开场只能使用 0 消耗的装备技能（近身制服/中距点射/远程狙击），
【交叉火力】需靠回合结束算力回复（100/回合）攒够 400——约第 4 回合末起才可施放，
成为需要玩家把握节奏窗口的「蓄力」机制。

## 改动（v0.685 → v0.686）

1. **js/Roles.js**（createDuoNengZhanJing）：构造后 `char.sp = 0`（覆盖 Character 默认满算力）。
2. **js/globals.js**：GAME_VERSION → v0.686。

## 行为说明（边界）

- 只影响**创建时**的初始算力：读档按存档 `sp` 恢复（loadAutoBattle 的 Object.assign 在创建后覆盖），
  撤退补位/休整等均不重置算力。
- AI 已有算力过滤（battleActions.js pickEnemySkill `actor.sp >= sk.spCost`）：
  0 算力时自动使用 0 消耗装备技能；算力 <400 前不会发起【交叉火力】（predictIntent 同理）。
- 算力回复时机不变：回合结束 regenSP +100（满 400 封顶）。
- 我方 AI 路线（decidePlayerAI）不涉及（多能战警玩家不可选）。

## 验证

适配 `check-v0686-sp0.js`：
- A 工厂创建后初始算力 0（maxSP 仍 400）；B 关卡 7 三员开场均 0 算力；
- C 回合结束回复 +100（0→100→200）；D 攒满 400 后 AI 才可选【交叉火力】；
- E 读档恢复存档算力（不为 0）；F 装备技能 0 消耗照常可用；G 无页面异常。
回归：check-v0685-gearfix.js（阵型方向）、check-v0684-duoneng.js（多能战警机制）。
